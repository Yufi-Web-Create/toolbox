# OPS-001: LINE inbound recovery, AI assistant, SNS setup guidance, and master operations portal

## Goal

Restore reliable LINE inbound delivery and add the operator-facing capabilities explicitly requested for OmniBox without weakening the existing tenant/RLS security model.

## Scope

1. LINE inbound recovery
   - Add an authenticated bridge repair path that re-applies and tests the configured LINE webhook.
   - Extend bridge health to report whether LINE credentials can be loaded and whether the configured webhook is active and points at OmniBox.
   - Make LINE provider-row lookup deterministic for the default LINE connection.
   - Improve safe bridge error logging without logging secrets.

2. AI reply assistant
   - Add a server-side AI reply-draft endpoint using the OpenAI Responses API.
   - Require a signed-in OmniBox user, tenant-visible conversation, and an AI-enabled plan.
   - Read the API key from server environment configuration only.
   - Add an AI draft button to the inbox composer and place the generated draft in the reply input for human review before sending.
   - Do not add an automatic-send path.

3. SNS setup guidance
   - Add detailed operator steps for LINE, Instagram, X, and Google/Gmail to the connected-accounts UI.
   - Update the SNS OAuth setup documentation to distinguish OmniBox-side steps from provider-console steps.

4. Master operations access
   - Make the icon at the top of the login screen open a dedicated master login screen.
   - Validate the master password only on the server from `OMNIBOX_MASTER_PASSWORD`.
   - Store only a signed, HttpOnly, secure session cookie in the browser.
   - Add a protected master operations/settings page that reports integration readiness without exposing secret values.

## Security constraints

- Never commit or log the requested master password.
- Never expose `OPENAI_API_KEY`, OAuth client secrets, LINE secrets, or service-role credentials.
- Do not weaken Supabase RLS.
- Do not add browser-side service-role usage.
- No database schema changes are authorized or required.
- No new npm dependency is required.

## Environment variables

- `OMNIBOX_MASTER_PASSWORD`: master password supplied only in the deployment environment.
- Vercel deployments use `VERCEL_OIDC_TOKEN` with Vercel AI Gateway automatically when available.
- `AI_GATEWAY_API_KEY`: optional AI Gateway fallback outside OIDC environments.
- `OPENAI_API_KEY`: optional direct OpenAI fallback when AI Gateway authentication is unavailable.
- `OPENAI_MODEL`: optional model override. The implementation has a safe default.
- Existing SNS and LINE environment variables remain unchanged.

## Acceptance criteria

- LINE health can distinguish bridge configuration, LINE connection, webhook URL match, and webhook active state.
- An authenticated owner can request a webhook repair without re-entering the LINE Channel Secret.
- AI draft generation is unavailable on non-AI plans and when the API key is not configured.
- AI-generated text is only inserted as a draft and is never automatically sent.
- Connected-accounts UI shows detailed setup operations for all four supported provider groups.
- Login-page icon opens master login.
- Master page cannot be opened without a valid master session.
- Master password is never present in committed source.
- Existing login/inbox/SNS/plan behavior remains intact.
